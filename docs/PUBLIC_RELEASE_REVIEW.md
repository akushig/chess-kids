# 공개 출시 완성도 및 Google Play 전환 검토

검토일: 2026-11-03~04 · 기준 빌드: `2026.11.03.2`

현재 소스, 기존 검수 기록, 360×780 Chromium의 신규 사용자 흐름을 검토했다. 규칙·상태 회귀 검사 57개는 이번 검토에서도 통과했다. 아래의 ‘재현’은 격리된 브라우저 프로필에서 확인한 결과다. 실제 어린이 관찰이나 Android 패키지 실기기 검증을 수행했다는 뜻은 아니다.

## 1. 판단

**게임의 기반은 갖췄지만 공개용 제품으로는 이용 흐름과 콘텐츠 편집을 더 마무리해야 한다.** Android 포장과 Play 신고만 완료해도 이 문제가 해결되지는 않는다.

지인 사용에서는 부모가 메뉴·목표·규칙을 설명하고 막힌 곳을 복구해준다. 공개 사용에서는 앱이 그 역할을 맡아야 한다. 현재 남은 가장 큰 차이는 ‘혼자 시작하고, 실패를 이해하고, 복구하고, 다음 놀이로 이어가는 경험’이다.

잘 갖춰진 기반:

- 표준 체스의 합법수·특수 수와 독립 국면 대조, 콘텐츠 해결 가능성 검증.
- 10단계 AI와 Worker 실행, 나이트 산책/탐험/투어 및 전체 경로·갈림길 도움.
- 보드 위치 고정, 체크·캐슬링·대국 종료의 명시적 안내.
- 프로필별 기록과 활동 세션, 되돌리기·이어하기, 오프라인 웹 캐시.

우선 필요한 것은 **진입·저장 신뢰성 → 목표와 조작의 시각적 통일 → 학습 순서 편집 → Android 통합과 실제 이용 검증**이다. 기존 규칙·콘텐츠를 재사용하면서 탐색·저장·공통 UI 계층을 정리하는 접근이 적절하다.

## 3. 공개판의 제품 방향

권장 중심은 **‘어린이가 혼자 배울 수 있고 가족이 함께 즐기는 체스’**다. 어린이 대상과 성인 취향을 연령 제한으로 나누기보다, 같은 앱에서 경험 수준에 맞게 접근하게 한다.

- **처음 해요:** 한 가지 추천 활동, 작은 보드, 그림 중심 목표, 짧은 성공.
- **조금 알아요:** 자유롭게 메뉴 탐색, 이어하기, 비슷한 기술의 다른 놀이.
- **도전하고 싶어요:** 전체 나이트 투어, 선택 도전, 표준 대전과 높은 AI 난이도.

현재의 모험·놀이터·대전 세 메뉴는 유지할 수 있다. 첫 진입부터 모든 규칙·설정을 읽게 하는 대신 가장 적절한 시작점과 ‘다른 놀이 고르기’를 함께 제공한다. 기존 사용자가 즐기는 전체 경로·갈림길 알림·가족 같은 판 기능을 입문 화면 간소화 때문에 제거하지 않는다.

### 첫 5분의 권장 흐름

1. ‘처음 해요’를 고르면 룩과 실제 깃발이 보이는 첫 과제로 바로 들어간다.
2. 기물을 한 번 고르고 깃발을 누르는 과정을 그림/짧은 시범으로 이해한다.
3. ‘같은 줄로 이동’, ‘연습 말 잡기’처럼 짧은 성공을 2~3번 경험한다.
4. 같은 룩으로 성 지키기의 짧은 상황을 해보고 배운 이동을 다른 장면에서 써본다.
5. ‘오늘 익힌 것’과 다음 추천 한 가지를 보고 계속하거나 편하게 끝낸다.

처음부터 대전하고 싶은 사용자는 바로 갈 수 있어야 한다. 처음 대전에는 이미 있는 ‘말이 적은 짧은 판’을 추천할 수 있지만, 표준 판도 명확히 고를 수 있게 한다. 표준 체스의 승패 조건을 바꾸기보다 첫 잡기·첫 체크 해결 같은 중간 성취를 표시한다.

### 콘텐츠별 편집 방향

| 콘텐츠 | 살릴 장점 | 공개판 보강 |
|---|---|---|
| 모험 | 짧은 문제, 직접 이동, 쉬운 룩 입문 | 전 기물의 입문 기준 통일, 실제 목표 아이콘, 선택 도전 분리, 다음 활동의 의미 연결 |
| 나이트 | 아이·어른 모두 즐길 수 있는 경로 탐색, 가족 시범 효과 | 신규 입문 목표와 기존 사용자 이어하기 구분. 산책→10칸→전체 투어의 성취 연결 |
| 한 수 발견 | 캡처·체크 해결을 실제 규칙으로 연습 | ‘설명 읽고 정답 고르기’에서 시각적 발견으로 전환. 비슷한 기술 문제를 충분히 반복하고 단계별 변형 추가 |
| 별/이동 수 도전 | 목표 순서와 경로를 생각하는 놀이 | 중복 규칙 정리. 제한 없는 기본 성공과 최적 경로 도전의 보상·설명 분리 |
| 성 지키기/왕 지키기 | 잡기와 안전이라는 서로 다른 역할 | 내 이동 후 상대가 어떻게 움직이는지 먼저 짧게 보여줌. 연습용 자동 이동과 실제 대전 규칙 차이를 눈에 띄게 표시 |
| 대전 | 10단계, 같은 기기 가족 대전, 표준 특수 수 | 기본 경고 유지, 안내 수준 선택, 쉽게 찾는 복구, 상대의 마지막 수와 그 이유 관찰. 성인용 기보·분석은 후순위로 검토 |

현재 활성 콘텐츠는 모험 48개, 한 수 발견 15개, 별 모으기 5개, 이동 수 도전 5개, 성 지키기 4개, 왕 지키기 4개다. 이 개수는 해결 가능성이 검증된 콘텐츠의 수이며, 장기 재미나 교육적 충분함을 입증하는 수치는 아니다.

문제 수를 일괄 늘리기 전에 각 문제에 `배우는 기술 / 선수 기술 / 새 규칙 / 계획 깊이 / 실패 후 복구 / 다음 연결`을 정의한다. 최소 이동 수만으로 아이의 체감 난이도를 판단하지 않는다. 특히 강제되는 규칙·분기·글 읽기 부담을 함께 본다.

## 4. 하나의 앱처럼 느껴지게 하는 기준

### 보드와 조작

- 목표는 깃발/별/명확한 상대 말로, 합법 이동은 점으로, 위험은 패턴·경고로 구별한다.
- 선택·마지막 수·위험·힌트의 색과 모양이 콘텐츠마다 다른 뜻으로 바뀌지 않게 한다.
- 되돌리기·도움·다시 하기의 위치와 뜻을 통일한다. 다시 하기는 진행을 잃을 수 있으므로 새 판과 구분한다.
- 이미 고정한 보드 위치를 유지하면서 주 행동은 화면 안에서 찾기 쉽게 한다. 추가 설정은 보조 패널로 옮긴다.
- 작은 폰에서는 8×8 칸이 약 40 CSS px 수준이 된다. 말 이름의 작은 글자만으로 식별하게 하지 말고 형태·선택 강조·되돌리기로 보완한다.

### 도움과 결과

- 도움은 ‘목표 다시 보기 → 왜 안 되는지 → 한 번 움직임 시범 → 필요하면 해법’ 순서로 제공한다.
- 전체 경로는 사용자가 원할 때 계속 사용할 수 있게 한다. 입문자를 위해 힌트 기능 자체를 없애지 않는다.
- 체크의 필수 경고와 학습용 설명을 구분한다. 숙련자가 반복 대국할 때 긴 설명을 매번 닫게 하기보다 학습 이력/안내 설정을 활용하되 체크·승패 표시는 항상 남긴다.
- 모든 결과 화면은 완료 여부, 이번에 해낸 것, 다음 행동을 같은 순서로 보여준다.
- 새로 개선한 대전 팝업의 접근성·초점·배경 입력 차단을 다른 모험/설정 팝업에도 공통 기준으로 적용한다.

### 성장·보상·가족 사용

별과 스킨뿐 아니라 ‘룩 이동을 혼자 해냈음’, ‘체크를 도움으로 해결함’처럼 무엇을 배우는지 보이게 한다. 이미 저장하는 도움/공동/독립 완료 정보를 활용할 수 있다. 도움받아 성공한 일을 실패처럼 취급하지 않는다.

꾸미기는 학습과 연결하되 기물의 기본 형태와 흰색/검은색 식별을 유지한다. 아이가 캐릭터만 외워 실제 체스 기물을 알아보지 못하는 상황을 사용성 검사에서 확인한다.

성인은 ‘전문 온라인 체스 서비스’ 수준의 기능을 모두 갖추지 않아도 전체 투어와 높은 AI, 가족 놀이로 즐길 수 있다. 간결한 설명·표준 기물·강한 도전 같은 선택을 제공하되 어린이 기본 흐름을 복잡하게 만들지 않는다.

출시 1차에서는 문의·기록 초기화·외부 이동을 부모가 이해하기 쉬운 영역으로 정리한다. 초등 저학년이 직접 읽기 어려운 메뉴와 설명에는 수동 듣기와 그림 힌트를 제공한다.

| 방식 | 이 프로젝트에서의 장점 | 보강 부담 | 판단 |
|---|---|---|---|
| 원격 URL을 여는 WebView | 빠르게 연결 가능 | 첫 로딩·통신·캐시·뒤로가기·오류 처리를 직접 다듬어야 함 | 공개판의 기준으로 삼기에는 운영·사용 경험 보강이 큼 |
| TWA/Bubblewrap | 기존 PWA와 브라우저 기능 재사용 | 도메인 소유 검증, 초기 오프라인 경험, 브라우저/웹 업데이트 의존 | 웹 중심 운영을 유지할 때 대안 |
| **Capacitor + 게임 파일 포함** | 기존 HTML/JS 재사용, 설치 후 첫 실행부터 핵심 게임을 오프라인으로 제공 가능, 네이티브 연결 | Android 프로젝트·저장·뒤로가기·생명주기 연결 필요 | **이 앱의 우선 권장안** |

이는 제품 특성에 근거한 추천이다. 프레임워크 이름만으로 Play 승인이나 품질을 보장하지 않는다. Google은 유용한 기능·안정적인 경험을 요구하고, 어린이 앱에도 웹뷰 관련 제한이 있다. 현재의 실제 게임 콘텐츠를 독립 앱 경험으로 다듬는 것이 중요하다. [기능·사용 경험 정책](https://support.google.com/googleplay/android-developer/answer/9898783?hl=en), [Families 정책](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)

Capacitor의 `server.url`은 개발용 원격 로딩 설정이므로 공개 빌드에서는 파일을 포함하는 구성을 권장한다. 배포 전용 디렉터리에 필요한 게임 자산만 모으고 개발용 파일과 권리 미확인 자산을 제외한다. [Capacitor 설정](https://capacitorjs.com/docs/config)

TWA는 앱과 사이트의 연관성을 Digital Asset Links로 검증한다. 현재 프로젝트 URL은 `/chess-kids/` 아래지만 검증 파일은 도메인 루트의 `https://akushig.github.io/.well-known/assetlinks.json` 위치가 필요하다. 이 저장소의 하위 폴더에만 추가해서는 충분하지 않으며 루트 배포 권한 또는 별도 도메인을 확인해야 한다. 루트 파일의 실제 존재 여부는 이번 도구 조회로 확정하지 못했다. [TWA 공식 설명](https://developer.chrome.com/docs/android/trusted-web-activity), [검증 파일 위치](https://developers.google.com/digital-asset-links/v1/create-statement)

권장 범위는 별도 게임 서버 없이 구현 가능하다. 정책 문서 공개 URL도 현재 정적 호스팅에 둘 수 있다.

## 6. Android로 옮길 때 반드시 보강할 부분

### A. 뒤로가기

현재 `showScreen()`은 DOM 화면을 바꾸며 브라우저 내비게이션 이력을 쌓지 않는다. 이를 그대로 감싸면 Android 뒤로가기가 앱 안의 의도한 이전 화면과 일치하지 않을 수 있다.

설계 순서: **열린 팝업 닫기 → 게임을 저장하고 상위 목록 → 홈 → OS 종료 동작**. 기물 선택 취소 같은 세부 동작도 화면별로 정한다. 모험의 월드/지도/진행 화면은 같은 `state.screen`을 쓰므로 실제 화면 경로를 별도로 관리해야 한다. 네이티브 뒤로가기와 생명주기 이벤트를 앱 탐색에 연결한다. [Capacitor App API](https://capacitorjs.com/docs/apis/app)

### B. 저장과 기존 이용자 기록

현재 기록은 `localStorage`에 저장한다. Capacitor는 모바일에서 그 데이터가 정리될 수 있어 네이티브 Preferences 사용을 권장한다. 단말 내 보관과 앱 삭제 후 소실 범위도 안내해야 한다. [Preferences 공식 문서](https://capacitorjs.com/docs/apis/preferences)

- `safeStore` 어댑터를 유지하면서 네이티브 저장소 연결과 부팅 시 초기 읽기 순서를 설계한다. 현재 동기 API에 비동기 저장소 이름만 바꾸면 초기화 문제가 생길 수 있다.
- 이동 완료 시점에 게임·되돌리기·획득 기록을 일관되게 저장한다. 강제 종료 직전의 이벤트에만 의존하지 않는다.
- 웹과 포함형 앱의 저장 origin이 달라질 수 있으므로 기존 웹 기록의 자동 공유를 전제하지 않는다. 필요하면 부모용 내보내기/가져오기를 제공한다.
- 계정 없는 기기 내 프로필과 온라인 계정은 다르다. 현 단계에서 클라우드 계정·계정 삭제 서버를 새로 만들 필요는 없다.

### C. 오프라인과 업데이트

현재는 최초 온라인 로딩 후 Service Worker가 캐시한다. 공개 앱은 설치 후 비행기 모드의 첫 실행부터 핵심 게임이 열리는 것을 권장한다.

게임·스킨·아이콘·폰트는 포함 자산으로 정리한다. 현재 `index.html`의 Google Fonts 외부 요청도 점검한다. 웹에서는 기존 SW 업데이트를 유지하고 포함형 Android 빌드에서는 앱 번들 버전과 SW 캐시가 충돌하지 않도록 분리한다. 웹의 ‘저장하고 업데이트’가 Android의 앱 업데이트처럼 보이지 않게 한다.

초기 Android 배포는 검증한 번들을 Play 업데이트로 제공하는 흐름을 권장한다. 원격 웹 코드 업데이트는 적용 범위·정책·호환성·롤백을 별도로 설계한다.

### D. 중단·복귀·화면·성능

현재 `visibilitychange` 처리와 저장은 있으나 실제 Android의 화면 꺼짐·앱 전환·프로세스 종료·복귀를 검증하지 않았다. 대전 안내를 읽던 상태, 승격 선택, AI 계산, 타이머 정지 이유를 복원해야 한다. 복귀 이벤트가 모든 멈춤을 무조건 해제하지 않도록 생명주기를 통합한다.

노치·상태바·제스처 영역을 피하는 네이티브 inset 처리가 필요하다. Android 16 대상의 edge-to-edge·뒤로가기 변경도 반영한다. 큰 화면의 회전/크기 조정 정책에는 게임 예외가 있으므로 세로 고정이 모든 경우에 금지된다고 단정하지 않는다. 그래도 태블릿·접이식·분할 화면은 실제로 검수하는 것이 좋다. [Android 16 변경점](https://developer.android.com/about/versions/16/behavior-changes-16)

지원할 OS와 WebView 하한을 정한다. 이 앱은 `:has()`, `dvh`, `inert` 등 비교적 새로운 기능을 사용한다. Android OS 버전만으로 WebView 호환성을 판단하지 않는다. 지원하지 않는 실행 환경에서는 빈 화면 대신 복구 안내를 제공한다.

9·10단계의 Worker 로딩·최대 계산 중 조작·발열·배터리·나가기 취소를 저사양 기기에서 검사한다. TTS는 현재 Web Speech API가 없으면 조용히 반환하므로 Android 음성 읽기의 실제 지원을 확인하고 필요하면 네이티브 TTS를 연결한다. 음성 출력 때문에 마이크 권한을 추가하지 않는다.

## 7. Google Play 공개 전 정책·배포 준비

### 권리 정리 — 실제 확인된 우선 항목

현재 스킨/화면 이름과 코드에 헬로카봇·티니핑·배달의민족이 있고 관련 캐릭터를 참고한 설명이 있다. 사용 허락 자료는 프로젝트에서 확인되지 않았다. 권리 침해를 확정하는 판단은 아니지만, **사용 권한 증빙 확인 또는 공개판에서 독자 캐릭터로 교체/제외가 필요하다.** AI로 다시 그렸거나 명칭만 바꿨다는 이유로 권리 문제가 해결됐다고 보지 않는다. 스토어 스크린샷·설명에도 같은 기준을 적용한다. [Google Play 지식재산 정책](https://support.google.com/googleplay/android-developer/answer/9888072?hl=en)

### 어린이 대상 신고와 개인정보

실제 어린이를 대상으로 하는 앱이므로 대상 연령·Families·IARC 콘텐츠 등급을 실제 경험에 맞게 신고해야 한다. 어른 프로필이 있다는 사실이 어린이 대상 요건을 없애지는 않는다. 실제로 검수한 연령대를 기준으로 선택하며 모든 연령을 일괄 선택하지 않는다. [Families 정책](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)

공개 개인정보처리방침 URL과 앱 내 접근 경로, 개발자/문의처, 보관·삭제 설명이 필요하다. 현재 전용 정책 페이지와 문의 화면이 없다. 개인정보를 수집하지 않는 앱도 개인정보처리방침 제출 요건이 있다. [사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)

Data safety는 앱 코드·SDK·개발자가 제어하는 WebView의 실제 데이터 흐름을 기준으로 작성한다. 현재 로그인·광고·분석 SDK가 없는 구조는 단순하지만 Google Fonts, 호스팅, 음성 서비스, 추가할 네이티브 SDK까지 확인한 후 ‘수집 없음’ 여부를 결정한다. 외부 통신이 있다는 사실만으로 모든 데이터 항목의 신고 여부를 단정하지도 않는다. [Data safety 공식 설명](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

개인정보처리방침은 쉽게 접근하게 하고, 문의·외부 링크·기록 초기화는 부모가 이해할 수 있도록 정리한다. 광고·계정·온라인 소셜 기능을 출시 1차에 추가하지 않으면 필요한 데이터·운영 범위를 작게 유지할 수 있다. 해당 기능을 추가할 경우 별도 정책 검토가 필요하다.

### 제출과 운영

- 2026-11-04 확인 기준, 새 앱과 업데이트는 Android 16/API 36 이상을 대상으로 해야 한다. [대상 API 요건](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
- 새 앱은 Android App Bundle 형식으로 제출한다. 패키지 ID, 서명/업로드 키, 단조 증가하는 `versionCode`, 버전 관리와 롤백 계획을 정한다. [AAB 안내](https://developer.android.com/guide/app-bundle)
- 선택한 SDK에 네이티브 `.so`가 포함되면 16KB 페이지 지원을 확인한다. 현재 HTML/JS 자체를 네이티브 라이브러리 문제로 취급할 필요는 없다. [16KB 지원](https://developer.android.com/guide/practices/page-sizes)
- 2023-11-13 이후 생성된 개인 계정에는 최소 12명 테스터의 연속 14일 비공개 테스트 후 프로덕션 접근 신청 요건이 적용된다. 기간이 지나면 자동 승인된다는 뜻은 아니다. 계정 유형과 적용 여부를 Play Console에서 확인한다. [테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
- 앱 아이콘·적응형 아이콘·시작 화면·스토어 이미지·지원 이메일·연락처·콘텐츠 등급·광고 유무·데이터 보안 정보를 준비한다. ‘친구와’는 현재 한 기기에서 하는 대전이므로 온라인 대전으로 오해시키지 않게 설명한다.

## 8. 공개 전 실제 이용 검증

자동 검사 통과는 필요한 기반이다. 이번 UX-01~04처럼 이용 동선과 화면 의미가 검사 범위에서 빠질 수 있으므로 다음 과제를 실제 어린이·부모·성인에게 관찰한다.

| 과제 | 관찰할 것 |
|---|---|
| 첫 과제를 시작하고 목표에 도달 | 설명을 읽지 못해도 목표·자기 말을 구별하는가 |
| 하던 놀이로 복귀 | 메뉴를 어디서 눌러도 저장판을 찾고 기록이 유지되는가 |
| 막힌 길에서 복구 | 왜 막혔는지 이해하고 되돌리기/도움을 스스로 찾는가 |
| 체크에서 왕 구하기 | 단순히 팝업을 닫는 것을 넘어 합법적인 대응을 실행하는가 |
| 한 놀이 완료 후 계속/끝내기 | 다음 행동을 선택하고 종료 후 다시 이어갈 수 있는가 |
| 보상 사용 | 별과 배운 내용, 꾸미기 획득을 연결해서 이해하는가 |
| 부모 시범 후 아이 차례 | 같은 판 시범·교대로 재미가 이어지는가. 독립 성공과 함께 성공을 구별하는가 |
| 성인 도전 | 불필요한 설명 부담 없이 높은 AI/전체 투어를 즐기는가 |

5~10가족의 짧은 탐색 테스트를 시작점으로 삼고, 며칠 뒤 재방문도 관찰하는 방법을 제안한다. 샘플 수 자체를 출시 승인 기준으로 삼지 않는다. 도움 요청 횟수·첫 성공까지 시간·반복 오조작·포기 지점을 기록하되 자동 추적 SDK가 반드시 필요한 것은 아니다.

Android 기기는 작은 폰·일반 폰·태블릿, 저사양·구형 WebView와 최신 Android 16을 포함한다. 비행기 모드 첫 실행, 업데이트 후 기록, 시스템 뒤로가기, AI 계산 중 이탈, 모달 중 잠금/복귀, 프로세스 종료 후 복원, 큰 글씨·TalkBack·무음·회전·제스처/3버튼 탐색을 점검한다. Play 사전 출시 보고서도 활용한다.

- 일반 메뉴 사용으로 기록을 잃지 않는다.
- 목표·규칙·불가능 이유·종료 상태를 서로 혼동하지 않는다.
- 아이가 최소 한 활동을 부모의 대신 조작 없이 시작하고 끝낼 수 있다.
- 기본 경로를 따라갔는데 선택 도전 때문에 갑자기 막히지 않는다.
- Android의 중단·뒤로가기·업데이트 후에도 게임과 기록이 유지된다.
- 앱에 포함한 모든 자산과 스토어 설명의 권리를 확인하고 신고 내용이 실제 동작과 일치한다.

1차 공개 범위는 오프라인 학습·10단계 컴퓨터·한 기기 가족 대전과 충분히 다듬은 놀이터로 잡을 수 있다. 온라인 대전·채팅·랭킹·계정·구독은 이후에 별도 설계해도 된다. Google Play에 올리기 위해 기능 수를 더 늘릴 필요는 없다.
