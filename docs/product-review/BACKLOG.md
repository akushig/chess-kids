# 실행 계획과 완료 기준

분석·설계 산출물이며 앱 기능은 아직 수정하지 않았다. 기능 추가 전에 오류와 복구 문제를 해결한다. 작업 크기는 상대 크기(S/M/L)이며 일정 약속이 아니다. 실제 개발 일정은 아래 1차 묶음의 구현 속도를 본 뒤 추정한다.

## 1. 권장 착수 순서

```text
M1 신뢰 회복
  판정·데이터 검증 + 모험 복구 + 불공정 별 + 힌트 화면 범위
       ↓
M2 혼자 계속할 수 있는 핵심 경험
  공통 세션·되돌리기 → 체크 구조대 → 룩 기본 길 → 나이트 짧은 목표
       ↓
M3 하나의 앱으로 연결
  고정 ID·저장 마이그레이션 → 이어하기·프로필 → 메뉴·성장·가족 놀이
       ↓
M4 완성 검수
  전체 활성 콘텐츠 재편집 → 성인 도전·정규 규칙 → 기기·오프라인·사용성 검증
```

이 순서는 처음부터 모든 모드를 다시 만드는 일을 피하면서도, 최종 완성에 필요한 일을 빠뜨리지 않기 위한 것이다. 출시할 준비가 안 된 콘텐츠는 실험실/비노출로 옮기고 기존 획득 기록은 보존한다.

## 3. 첫 구현 묶음의 정확한 범위

첫 묶음에서 완료할 결과:

1. 룩·킹 회피 미션에서 위험 이동 후 아무 반응 없이 멈추는 상태 제거.
2. 검증되지 않은 퍼즐을 성공 처리하거나 불법 수를 요구하지 않도록 교정/숨김.
3. 수집 1단계의 제한 여유와 별 기준, 폭탄 최고 보상, 나이트 부분 보상 오류 교정.
4. 현재 화면에만 힌트가 붙고, 나간 뒤 팝업·AI 응수가 끼어들지 않도록 정리.
5. 대전 체크 시 공격자·왕·합법 대응 표시와 한 수 시범의 최소 기능.

새 콘텐츠·신규 테마 없이도 사용자 불신과 막힘을 가장 크게 줄일 수 있는 묶음이다. 이때부터 어린이 짧은 테스트를 시작하고 이후 구조 변경의 기준으로 삼는다.

## 4. 기능별 인수 시나리오

### 모험

- Given 룩 회피 미션, When 위험한 이동, Then 공격선과 실패 이유를 표시하고 현재 화면에서 복구할 수 있다.
- Given 폰이 목표를 지나쳐 해결 불가능한 상태, Then 모호한 정지 대신 되돌리기/재시작을 제안한다.
- Given 새로 온 사용자, When 모험 지도 진입, Then 현재 가능한 단계가 보인다.
- Given 수업 중 도움 사용, When 목표 달성, Then 완료 도장을 받고 다음 기본 활동으로 갈 수 있다.
- Given 킹 포획 수업, When 잡은 칸이 다른 적의 공격 범위, Then 안전한 수로 성공 처리하지 않는다.

### 퍼즐

- 목표와 합법성을 독립 엔진으로 검증한다. 출제 엔진과 채점 엔진이 같은 오류를 공유하는 테스트만으로 끝내지 않는다.
- 지정 해답뿐 아니라 목표를 충족하는 대체 정답이 인정된다.
- 2수 문제는 가능한 모든 상대 응수에 대해 목표 달성 경로가 있다. 대표 응수만 재생하는 모드라면 그 의미를 명시한다.
- 오답 뒤 원래 국면과 차례로 돌아갈 수 있다.
- 상대 응수 대기 중 상대 말을 조작할 수 없고, 화면 이탈 후 응수가 남지 않는다.
- 마지막 문제를 마치면 결과·다음 활동·종료가 있다.

### 대전

| 상황 | 기대 결과 |
|---|---|
| 직선 체크 | 공격선과 킹, 실제 대응 가능한 말 표시 |
| 공격자 포획 가능 | 킹 이동 외 포획도 해결로 안내 |
| 중간 차단 가능 | 합법적인 막기 수 제시 |
| 나이트 체크 | 나이트를 막는 잘못된 제안 없음 |
| 더블 체크 | 실제 합법수만 안내 |
| 핀된 기물 이동 | 왕을 드러내는 원인을 미리보기로 설명 |
| 폰의 공격선 | 전진과 공격 칸을 혼동하지 않음 |
| 체크메이트 | 입력 불가 이유와 끝난 판임을 명시 |
| 스테일메이트 | 체크와 다른 무승부 이유 표시 |
| 앙파상으로 체크 해소/노출 | 제거되는 폰까지 반영 |
| 승격·캐슬링 후 되돌리기 | 말·권리·차례·기록·시계 복원 |
| AI 계산 중 나가기·재시작 | 이전 수가 새 판에 적용되지 않음 |
| 친구 시계 0 / 도움 중 | 자동 이동 없음 / 설정대로 시계 정지 |

[lesson-examples.json](lesson-examples.json)의 8국면은 이 표 중 일부의 검증된 출발점이다. 앙파상·캐슬링 등 추가 회귀 국면은 구현 시 보충한다.

### 나이트·다른 놀이

- 산책 목표는 적어도 하나의 검증된 경로를 갖는다. 무작위 생성 시 시드와 검증 결과를 저장한다.
- 되돌리기 후 방문 칸·별·콤보·턴·솔버 상태가 모두 일치한다.
- 힌트가 존재하는 경로를 안내하고, 탐색 한도 초과를 ‘불가능’이라고 표시하지 않는다.
- 완주 실패 뒤 전체 초기화 없이 갈림길까지 돌아갈 수 있다.
- 디펜스는 생명과 실제 실패 임계값, 경계와 돌파 위치가 일치한다.
- 순찰·생존 모드는 적 다음 행동을 예고하고 예고대로 움직인다. 예고가 확률이라면 확정 표시처럼 보이지 않는다.

### 저장·플랫폼

- 이전 저장 형식의 실제 형태를 테스트 데이터로 만들어 migration 전후 별·해금이 보존되는지 확인.
- 탭 종료·새로고침·화면 이탈·새 버전 활성화·저장 쓰기 오류를 각각 테스트.
- 형제/부모 프로필 전환 시 다른 사람의 판이나 숙련 기록이 덮이지 않음.
- 오프라인 재실행 시 모든 앱 스크립트·스킨·아이콘·필수 음성이 준비됨.
- 작은 휴대폰/큰 휴대폰/태블릿/PC, 마주 보기/같은 방향 보기 검수.
- 확대, 음소거, 동작 감소, 키보드, 스크린리더의 목표·차례·결과 상태를 확인.

## 5. 콘텐츠 검수 자동화

출시 콘텐츠에 공통으로 적용할 검사:

1. 보드 범위·좌표 중복·기물 존재·목표 수 등 스키마 검증.
2. 최소 1개 해법 존재. 회피·제한 수는 그 조건까지 포함.
3. 힌트의 첫 수가 현재 상태에서 유효하고 목표 달성 경로를 유지.
4. 최고 보상 조건이 실제 달성 가능. `par`는 솔버 결과 또는 검수된 증거로 저장.
5. 표준 체스 퍼즐은 합법 국면·합법 수·실제 체크/메이트/포크·응수 트리 검사.
6. 상태 전이 후 보드와 안내·버튼이 일치. 중간 실패·완료·취소에서 복구/종료 경로 존재.
7. 모든 활동에 이름·목표·도움·성공·복구·다음 행동 문구가 있음.
8. 새 개념 수·선수 기술·도전 조건 메타데이터 존재.

무작위 게임은 ‘몇 번 해 봤다’를 검증의 전부로 삼지 않는다. 시드 기반 재현, 알려진 경계 사례, 상태 불변식(중복 점유 없음 등)을 자동 검사한다. 끝없는 게임의 모든 판을 해결 가능하다고 주장하지 않으며, 입문 추천에는 검증된 배치를 사용한다.

현재 재현 방법:

```sh
node docs/product-review/evidence/audit.cjs > /tmp/chess-audit-results.json
python3 -m venv /tmp/chess-review-verify
/tmp/chess-review-verify/bin/python -m pip install chess==1.11.2
/tmp/chess-review-verify/bin/python docs/product-review/evidence/verify-puzzles.py
/tmp/chess-review-verify/bin/python docs/product-review/evidence/verify-examples.py
```

주의: 두 Python 스크립트 중 퍼즐 검증기는 동봉된 `evidence/audit-results.json`을 읽는다. 앱을 수정한 뒤 최신 데이터로 다시 검사하려면 Node 결과를 그 파일로 갱신하거나 읽는 경로를 변경한다. 현재 Node 검증은 DOM·시간을 대체하므로 브라우저 E2E 테스트를 대체하지 않는다. 소스 해시가 결과에 들어 있어 어떤 버전을 검사했는지 확인할 수 있다.

## 6. 어린이·성인 플레이테스트

### 첫 소규모 표본

체스 처음인 어린이, 말 이동은 아는 어린이, 대전 경험이 있는 어린이, 부모/성인을 각각 포함한다. 5~7세·8~10세·11세 이상을 가능한 범위에서 섞되, 모집 편의에 따른 소규모 관찰이라는 점을 명시한다. 8~12명 정도의 첫 관찰은 주요 사용성 장애 발견용이며 통계적 일반화나 교육효과 입증용이 아니다.

기록할 사전 정보는 연령대, 읽기 도움 여부, 체스 경험, 평소 기기다. 어린이에게 시험처럼 규칙을 설명하게 요구하지 않는다. 행동으로 이해 여부를 본다.

### 과제

1. 설명 없이 홈에서 활동 하나 시작하기.
2. 새 룩 기본 길에서 1수·2수·장애물 단계를 진행하기.
3. 체크 국면에서 처음에는 스스로 시도하고, 필요하면 앱 도움으로 안전하게 만들기.
4. 나이트에서 의도적으로 막힐 수 있는 지점에 도달한 뒤 회복하기.
5. 부모 시범을 본 뒤 같은 판, 이어서 배치가 바뀐 판을 아이가 하기.
6. 활동을 마친 뒤 다음 선택, 나갔다가 이어하기.
7. 숙련 사용자는 완주·최적화·정규 대전에서 도전감을 평가하기.

부모는 첫 시도에서 정답을 바로 알려 주지 않되 아이가 불편해하면 즉시 돕거나 중단한다. ‘혼자 하기’와 ‘부모 시범 후’ 순서를 일부 참가자에서 바꿔 단순한 반복 학습과 사회적 효과를 혼동하지 않게 한다. 자녀 한 명의 선호만으로 전체 난이도를 결정하지 않는다.

### 무엇을 측정할까

| 지표 | 정의 | 첫 목표(제품 가설) |
|---|---|---|
| 시작 가능 | 어른의 길 안내 없이 활동 시작 | 관찰 세션 80% 이상 |
| 막힘 복구 | 잘못된 시도/길 막힘 뒤 앱 도움만으로 유효 행동 재개 | 80% 이상, 빈도·시간 함께 기록 |
| 체크 이해 전이 | 첫 구조대 경험 뒤 다른 배치에서 합법 대응 | 70% 이상 |
| 작은 성공 | 첫 활동 시작 후 도움 포함 목표 하나 달성 | 대다수가 2분 이내 |
| 다음 선택 | 활동 종료 후 다음 놀이 또는 종료를 스스로 선택 | 무반응 종료 화면 0개 |
| 부모 개입 | 규칙·조작 설명을 위해 직접 개입한 횟수 | 기존 버전보다 감소 |
| 반복 의향 | 계속하고 싶은지, 다음 방문 때 실제로 다시 고르는지 | 답변과 실제 행동을 함께 관찰 |
| 성인 도전 가치 | 숙련자가 고급 모드를 스스로 재시도하는지 | 쉬운 모드와 분리해 정성 평가 |

작은 표본에서 80% 등 숫자는 강한 통계적 증거가 아니다. 큰 개선 여부를 판단하는 운영 기준으로 쓰고 사용자 수와 실패 사례를 함께 보고한다. 성공률을 높이기 위해 문제를 전부 자동으로 대신 풀면 목표를 달성한 것으로 보지 않는다.

### 최소 이벤트

```text
activity_started, move_attempted(reason), valid_move
help_opened(level), demo_played, undo_used, dead_end_detected
objective_completed(assistance), activity_exited, session_resumed
next_activity_selected, profile_role(child/adult/demo)
```

학습을 위해 꼭 필요하지 않은 신원·음성·원본 화면 녹화는 기본 수집하지 않는다. 첫 버전은 로컬 테스트 로그로도 충분하다. 성과 측정의 목적은 장시간 붙잡아 두기보다 어디서 이해·복구가 끊기는지 찾는 것이다.

## 7. 최종 출시 조건

- 활성 고정 콘텐츠의 합법성·해결 가능성·최고 보상 검증 통과율 100%.
- 알려진 진행 불능·잘못된 성공·오프라인 누락 P0 없음.
- 체크·핀·경로 막힘에서 이유와 유효한 다음 행동이 제공됨.
- 모든 실패·완료·마지막 단계에 복구 또는 종료 경로가 있음.
- 기본 학습 길에서 새 규칙이 예고 없이 동시에 늘지 않음.
- 지원 수준을 높여도 규칙이 조용히 바뀌지 않음.
- 새로고침·이탈·업데이트·프로필 전환으로 진행·기존 보상을 잃지 않음.
- 어린이의 혼자 하기·부모와 함께 하기·숙련자 도전 세 경로를 관찰 검수함.
- 주요 기기 화면·터치·음성 없음·접근성·오프라인 QA를 완료함.
- 실험 콘텐츠는 주 추천에서 제외하고, 콘텐츠 수를 늘리기 위한 미검증 문제를 넣지 않음.

완성 여부는 메뉴 수나 새 스킨 수로 판단하지 않는다. **이유를 알 수 없는 막힘, 억울한 실패, 잘못된 정답, 다음 행동이 없는 끝**이 사라졌는지가 기준이다.
