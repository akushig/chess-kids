## 3. 세부 결정

- **상태 원본**: 선택은 `lesson.selected` 하나만 쓴다. `game.selected`는 항상 비운다. 진행 중 선택은 저장하지 않는다(명세 §8). 수업 1의 지목 결과는 시도 내용이라 결과 화면과 함께 저장한다.
- **저장 정규화**
  - 응수 중(`response`)에 저장하면 시도 시작의 `choose`로 남기고, 방금 쌓은 시도 시작 기록은 빼고 저장한다(되돌리기 버튼이 같은 상태를 가리키지 않게).
  - 시범 중(`demoPlaying`)이면 시범 전으로 남긴다. 시도 수는 결과가 나올 때 센다.
  - 그래서 복원 직후에 말이 저절로 움직이지 않는다.
- **복원 검증**: 저장된 판을 그대로 쓰지 않는다.
  - 신뢰된 교재 FEN과 기록된 학생 수(그 장면의 후보에 있어야 함), 그에 따른 사전순 응수로 판을 다시 만들어 비교한다. 다르면 거절한다.
  - 되돌리기 기록도 같은 수업·같은 장면이어야 한다. 모르는 ID·버전, 잘못된 단계, 다른 장면의 시작 배치, 범위 밖 좌표, 120개 초과 기록, `<`가 든 문자열을 거절한다.
- **되돌리기**
  - 한 연습(장면) 안에서만 쓰고, 다음 장면으로 가면 기록을 비운다.
  - 마무리는 혼자 해보기 장면의 한 단계라서, 마무리 뒤 되돌리기는 혼자 해보기의 시도 시작으로 돌아간다.
  - 되돌리기·재시도 뒤에도 시도 수, 도움 기록, 이미 얻은 성공은 줄이지 않는다.
  - `다른 방법으로`는 그 시도를 되돌리는 것과 같다(기록 맨 위의 시도 시작을 꺼낸다).
- **도움 단계**: 도움은 수를 대신 두지 않는다. 재시도하면 화살표는 지우고 도움 단계·기록은 남긴다.
  - 수업 1: 명세대로.
  - 수업 2의 도움 2(`선택한 목적지가 공격받는 이유`): 시도 전에도 쓸 수 있도록, 위험한 목적지 전부를 빗금으로 표시하고 그 칸을 잡는 상대 말에서 화살표를 긋는다(직전에 실패한 칸 포함).
  - 수업 3: 명세에 도움 단계가 없어 같은 구조로 정했다. ① 잡을 수 있는 폰 ② 되잡히는 폰과 되잡는 말의 화살표 ③ 안전한 잡기 화살표.
- **수업 1의 왕 지목**: 정답 집합에서 왕을 뺐다. 왕을 누르면 일반 오답(`이 말은 지금 바로 잡히지 않아요…`)으로 처리하고 시도로 센다. 검은 말·빈칸은 `흰색 우리 말 중에서 골라요` 안내만 하고 시도로 세지 않는다.
- **수업 3의 빈칸 이동**: 룩을 고르면 합법 목적지를 모두 점으로 보여주고, 잡을 수 있는 칸은 테두리로 구별한다. 빈칸을 누르면 `이번에는 폰을 잡는 두 방법을 비교해요.` 안내만 하고 시도로 세지 않는다.
- **완료 기록**
  - `lesson_progress_v1`의 completed는 함께·혼자 해보기 성공 뒤 마무리에 닿을 때만 기록한다. assisted/independent는 혼자 해보기에서 도움을 썼는지로 나눈다.
  - 마지막 장면은 장면마다 기록한다.
  - 별·새 보상은 없다. `내가 익힌 것`에 `체스 수업 · 제목` 줄만 추가했다.
- **시범 간격**
  - 말이 움직이는 단계는 이동 뒤 약 700ms를 둔다.
  - 글만 바뀌는 단계와 `동작 줄이기`에서는 1400ms(읽을 시간)를 둔다.
  - `⏭ 끝 장면 보기`·`직접 해보기`로 언제든 건너뛸 수 있다. 수업 1의 시범은 `예측 · 상대 차례라면` 표시가 붙은 복제 판에서만 흑의 잡기를 보여주고 원래 판으로 돌아온다.
- **설명 창(`왜 그런가요?`)**: 열려 있는 동안 예약된 응수·시범은 멈춘다. 닫으면 한 번만 이어간다.
- **연타 방지**
  - 진행 버튼이 단계를 바꾼 직후 450ms 동안은 같은 자리의 다음 버튼을 무시하고, 판을 누르면 해제한다.
  - 브라우저 검사 중 `수업 마치기`를 두 번 탭하면 마무리 화면을 건너뛰고 다음 수업으로 넘어가는 문제를 발견해 넣었다.
- **대전 연결**
  - 마지막 수업 오른쪽 `대전에 써보기`는 대전 입구(난이도·모드 선택)로 간다.
  - 모든 수업의 보조 `⚔ 이 배치로 대전`은 혼자 해보기의 원래 초기 배치를 보여주고 컴퓨터 난이도를 고른 뒤 시작한다.
  - `lessonPractice`는 lessonId·lessonVersion이 교재와 같고 sceneId가 그 수업의 혼자 해보기 장면일 때만 유효하다. 재대결은 같은 배치·같은 난이도다.
- **화면 치수**
  - 헤더 44px + 단계 26px + 설명 96px + 판 + 도구 48px + 진행 48px.
  - 판 너비는 `min(100%, max(260px, 100dvh − 308px))`, 최대 440px.
  - 가로 화면처럼 너무 작아지는 경우 판을 260px 아래로 줄이지 않고 세로 스크롤을 허용한다(640×360, 320×568 측정 시 가로 넘침 없음).

## 5. 남은 교육 검수와 사용자 관찰

체스 지도자에게 받을 검수 항목:

3. 수업 2에서 체크를 주는 `Re8+` 같은 수도 다음 수에 잡히지 않으면 성공으로 인정하는 점.
4. 수업 1에서 왕을 지목했을 때 일반 오답 문구로 처리하는 점.
5. 시범 문구와 도움 단계의 순서.

실제 사용자 관찰(명세 §11, 구현 후 별도):
- 첫 설명 없이 시작했을 때 처음 막히는 곳, 되돌리기·도움을 쓰는지, 다른 배치(혼자 해보기)에서 혼자 성공하는지.
- 다음 수업을 스스로 고르는지, `이 배치로 대전`을 쓰는지.
- 기록 양식: 날짜 / 경험 / 수업 / 첫 막힘 / 필요한 설명 / 다른 배치에서 혼자 성공했는가 / 다음 수업을 스스로 선택했는가 / 대전에 사용했는가.

실기기에서 볼 것:
- 360×640급 휴대폰에서 판과 하단 버튼이 한 화면에 들어오는지.
- 시범 간격(700ms/1400ms)이 읽기에 충분한지.
- 한국어 음성 읽기와 `동작 줄이기`.

3개 수업에서 자발적 사용과 학습 전이를 확인하기 전에는 유료 과정 제작·가격 실험을 시작하지 않는다(명세 §11).

## 6. 첫 사용자 확인 뒤 수정 · 빌드 `2026.11.07.2`

배포 직후 사용자가 실기기로 해본 결과는 다음과 같았다.
- 무엇을·어떻게 하는지, 내가 흑인지 백인지, 화살표의 말이 누구 것인지 알 수 없었다.
- 말을 누르면 안내는 나오지만 그다음 무엇을 누를지 몰랐다.
- 수업을 처음부터 다시 하는 방법을 찾지 못했다.
- 홈의 버전 글자가 밝은 배경에서 흰색이라 보이지 않았다.
- 판이 움직이지 않는 것은 확인했다.

자동 검사는 이 문제들을 잡지 못했다(규칙·배치만 검사했다). 고친 것:

- **내 편 표시**: 상단 단계 줄 오른쪽에 늘 `우리 = 흰색` 표시를 두었다. 판의 모든 말에 `우리`(파랑)/`상대`(진한 갈색) 표시를 붙였고, 읽기 프로그램용 칸 설명에도 넣었다.
- **지금 할 일**
  - 설명 영역이 단계마다 `👉 다음에 누를 것`을 말한다.
  - 수업 1: `우리(흰색) 말을 눌러 알려 주세요. 말은 움직이지 않아요`.
  - 수업 2·3: `① 파란 테두리의 우리 말을 눌러요` → `② 점이 찍힌 칸 중…`.
  - 결과 뒤에는 무슨 일이 일어났는지(`빨간 화살표처럼 상대 룩이 와서 우리 비숍을 잡았어요`)와 다음 버튼 이름을 함께 적는다.
  - 다음에 누를 버튼은 노란 테두리로 반짝이고(동작 줄이기에서는 테두리만), 처음 누를 우리 말은 파란 테두리가 깜박인다.
  - 시범 중이나 결과 뒤에 판을 누르면 다음 할 일을 안내하거나 다음 버튼을 흔들어 보인다.
- **수업 소개**
  - 새로 시작한 수업은 먼저 소개 창을 띄운다: 배울 것 / 우리 = 흰색·상대 = 검은색 / 조작 방법 / 세 단계 / 색의 뜻 / 왜 그런가요.
  - 창에서 `▶ 시범 보기` 또는 `바로 해보기`를 고른다. 이어할 때는 띄우지 않는다.
  - 도구 줄의 `❓ 왜 그런가요?`는 같은 내용의 `❓ 방법과 이유`로 바꿨다. 명세의 설명 창 계약(초점 가두기, Escape, 응수 정지)은 그대로다.
- **처음부터 다시**
  - 수업 화면 위에 `↺ 처음부터`(확인 뒤 시범부터, 해본 기록 유지)를 두었다.
  - 목록의 진행 중 카드에는 글자 링크 대신 `↺ 처음부터 다시`(왼쪽)·`▶ 이어하기`(오른쪽) 버튼을 둔다.
- **문구**
  - 성공·실패 문장에 `우리`/`상대`를 넣었다. 예: `폰은 잡았지만 상대 비숍이 우리 룩을 다시 잡았어요`, `이 칸에서는 상대가 다음 한 수에 우리 비숍을 잡을 수 없어요`.
  - 명세 §5의 문장을 이 방향으로 고쳤다. 판정 술어와 교재 배치는 바꾸지 않았다.
- **홈 버전 글자**: 짙은 회청색으로 바꿨다. 같은 규칙이 두 군데 있어 둘 다 고쳤고, 브라우저 검사가 글자색을 확인한다.
- **화면 치수**
  - 헤더(제목 두 줄까지 + `↺ 처음부터`)는 44px, 단계 줄은 28px이다.
  - 360×640에서 모든 조작이 한 화면에 들어오고, 판 좌표 불변 검사도 그대로 통과한다.

검증

- `npm run test:browser` 15개 묶음 통과.
- 수업 브라우저 검사 추가 항목: 소개 창 내용, 시범 중 판 누름 안내, 우리/상대 표시, 결과 뒤 다음 버튼 강조·문구, 수업 안·목록의 처음부터 다시, 버전 글자색.

## 8. v2 재설계 · 빌드 `2026.11.07.3`

2차 수정 뒤에도 사용자는 "진행이 여전히 어색하다, 무엇을 하는 콘텐츠인지 모르겠다"고 했다. 고치기 전에 방향을 먼저 검토했다.

- 리체스 학습 메뉴(같은 주제의 보호·전투 단원)와 듀오링고 체스를 확인했다.
- 우리 앱의 다른 놀이와 조작 방식을 비교했다.
- 결론: 성인이라서가 아니라 구조 문제다. 사용자가 고른 방향은 "직접 두고 둔 수를 설명"이다.

구현:
- 수업 3개 × 5판을 엔진으로 설계했다.
- 판마다 다음 과정을 반복한다: 목표 한 줄 → 내가 한 수 → 위험하면 상대가 실제로 잡음 → 한 문장 설명 → 다시/다음.
- 상대 말을 누르면 그 말이 갈 칸을 보여 준다.
- 힌트는 두 단계다.
- 시범·지목·보기/함께/혼자·소개 창은 없앴다.
- 예전 v1 수업 자료는 오류 없이 버린다.

검증

- `npm run test:browser` 15개 묶음 통과(수업 검사는 15판을 실제 탭·키보드로 진행).

## 9. v3: 45판·단계·성공 표시 · 빌드 `2026.11.07.4`
