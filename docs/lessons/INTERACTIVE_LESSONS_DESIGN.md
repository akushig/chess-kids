## 1. 첫 구현 범위와 제품 목표

앱 내 이름: **체스 수업**. 첫 과정: **내 말 지키기 · 첫 세 수업**.
말의 움직임은 대략 알지만, 상대 위협을 놓치거나 잡자마자 되잡히는 아이·성인 입문자를 대상으로 한다.
목표는 사용자가 다른 배치에서도 상대의 공격을 찾고 자기 선택의 결과를 이해하는 것이다.

이번 완제품 범위: 과정 목록 1개 / 수업 3개 / 수업마다 시범 1·함께 연습 1·혼자 적용 1, 총 9개 학습 장면 / 재도전 / 단계별 도움 / 이어하기 / 프로필 파일 이동 / 각 수업에서 표준 대전으로 연결.
모두 무료 체험으로 제공한다. 결제·가격·잠금·구독·AI 채팅·대국 자동 분석·영상 제작·새 계정·서버·분석 SDK는 구현하지 않는다. 기존 기능은 무료 그대로다.

연령별 프로필이나 기능 차이를 만들지 않는다. 사용자가 수업을 직접 고른다. 수업 순서는 추천이며 앞 수업 미완료로 뒤 수업을 잠그지 않는다. 기존 AI 10단계는 학습 단계나 Elo로 취급하지 않는다.

## 2. 전체 과정의 확장 방향 (이번 구현 밖)

|과정|선수 경험|학습 목표|
|---|---|---|
|처음 한 판|없음|말 움직임·체크·승패. 기존 모험과 무료 안내를 연결|
|내 말 지키기|이동·잡기 이해|공격 찾기, 피하기, 되잡힘 확인. 이번 체험 과정|
|공격 기회 찾기|기본 대전|양면 공격·핀·유인. 추가 유료 과정 후보|
|유리한 판 끝내기|기본 대전|룩/퀸 메이트·승격·스테일메이트|
|계획하며 두기|기초 전술|전개·왕 안전·말의 활동·폰 구조 입문|

초기 판매 후보는 독립적으로 끝낼 수 있는 주제별 일회성 과정이다. 가격과 유료 전환은 별도 결정한다. 체험판을 자동으로 유료 전환하지 않는다. 기존 규칙 설명·오류 복구·힌트를 결제로 제한하지 않는다. 제작량 증설보다 실제 다른 배치로의 학습 전이를 먼저 관찰한다.

## 3. 진입과 화면

- 홈의 주 진입 3개 유지. 보조 진입에 `체스 수업` 카드 추가: `상대의 공격을 보고 내 말을 지켜요 · 체험 3수업`.
- 대전 설정에서도 `체스 수업` 보조 버튼 제공. 진행 중 대전 위에 수업을 강제로 띄우지 않는다.
- 목록은 3개 카드와 해당 수업의 상태: 처음 / 이어하기 / 해봤어요. 번호·제목·배울 행동 한 줄만 우선 표시.
- 처음 들어오면 다른 게임의 이어하기를 표시하지 않는다. 수업별 진행을 보존하며 다른 수업 선택 시 기존 진도를 지우지 않는다.
- 수업 단계: `보기 → 함께 해보기 → 혼자 해보기`. 상단 1/3 같은 간결한 표시. 고정된 설명 영역+체스판+하단 행동 영역.
- 주 안내는 1~2문장, 한 번에 한 행동. 오른쪽 주요 버튼은 `직접 해보기`/`다음 연습`/`수업 마치기`. 왼쪽 보조 버튼은 `다시 보기`/`목록`.
- 360×640에서도 판과 필수 조작(되돌리기·도움·다음)이 화면 안에 들어와야 한다. 판 크기는 단계 전체에서 동일하게 예약한다. 설명·결과 길이에 따라 판이 이동하면 안 된다.
- 최소 조작 버튼 44px. 글자 확대/가로 화면 등 모든 요소를 무리하게 축소해야 하는 경우에는 읽을 수 있는 스크롤 대안을 허용하되 일반 세로 화면 기준을 충족한다.
- `왜 그런가요?`는 선택형 모달. 자세한 설명을 확인하는 동안 이동·자동 응수 정지. 모달 초점 가두기/Escape/닫은 뒤 원래 초점 복귀.
- 기존 말 스킨·기물 이름 배지·키보드 판 이동·음성 읽기·동작 줄이기 설정을 적용한다. 음성은 안내 버튼을 눌렀을 때 또는 기존 음성 설정에 따른다. 소리를 켜야만 진행할 수 있으면 안 된다.

## 4. 수업 흐름과 상태 전이

각 수업은 다음 고정 흐름이다.

1. **보기**: 처음 판과 한 줄 목표. `시범 보기`를 누르면 공격선/나이트 착지점 강조→실제 이동→잡힘/안전 결과를 순서대로 보여준다. 자동 시작 안 함. `다시 보기`와 `직접 해보기` 제공. 시범은 자유롭게 건너뛸 수 있다.
2. **함께 해보기**: 안내 있는 새 배치. 첫 입력 전에는 정답 칸을 표시하지 않는다. 이동 수업에서 말을 선택하면 합법 목적지는 보여준다.
3. **결과 살펴보기**: 성공/위험을 판 위에서 확인. 실패는 생명·감점 없이 `다른 방법으로` 버튼으로 그 시도의 시작 위치로 돌아간다. 자동으로 되돌리지 않는다.
4. **혼자 해보기**: 다른 배치, 같은 개념. 도움은 항상 이용 가능. 도움 없이/도움으로 완료를 구분해 저장하되 별/진행을 차감하지 않는다.
5. **마무리**: 배운 행동 한 문장. 왼쪽 `수업 목록`, 오른쪽 `다음 수업`(마지막 수업은 `대전에 써보기`). 보조 `이 배치로 대전` 제공.

상태 필드 phase: demoReady/demoPlaying/choose/response/result/complete. sceneRole: demo/guided/transfer.
result는 success/retry. illegal input은 시도 완료로 세지 않는다. 재시도 시 이전 support 기록은 남기고 현재 선택/화살표/임시 응수는 초기화한다.

자동 응수는 학생이 수를 둔 뒤 대략 500ms 여유 후 애니메이션으로 보여준다. 시범에서 단계 사이 간격은 약 700ms, 동작 줄이기에서는 애니메이션을 생략하되 설명을 읽을 수 있어야 한다. 입력은 응수/이동 중 잠근다. 홈/프로필/다른 수업 이동 시 예약 콜백을 취소한다.

되돌리기는 **학생 선택과 그에 따른 교재 응수를 한 묶음**으로 되돌린다. 응수 재생 중에는 비활성. 완료 뒤 되돌리면 해당 연습을 다시 시도할 수 있으며 이미 얻은 완료 기록을 삭제하지 않는다.

## 5. 정확한 콘텐츠 정의

좌표 표기는 문서에서는 체스 좌표, 코드에서는 [row,col] = [8-rank,fileIndex]. 모든 장면은 백이 학습자, 백 차례, 캐슬링/앙파상 없음. UI에 FEN을 표시하지 않는다.

### 기준 배치

|코드|FEN|핵심 내용|
|---|---|---|
|A|`7k/6b1/8/8/3R4/8/K7/8 w - - 0 1`|g7 비숍이 d4 룩을 노림. 백 왕 a2는 그 대각선 밖|
|B|`r6k/8/8/8/8/B7/8/4K3 w - - 0 1`|a8 룩이 a3 비숍을 노림|
|C|`7k/8/5n2/3R4/8/8/8/K7 w - - 0 1`|f6 나이트가 d5 룩을 노림|
|D|`7k/1b6/8/8/4p3/8/4R2p/K7 w - - 0 1`|백 e2 룩: e4 폰을 잡으면 b7 비숍에게 잡힘. h2 폰은 안전하게 잡을 수 있음|

mirror(X)는 모든 행의 좌우를 반전한 배치다. 차례/캐슬링 없음은 유지. 기물을 바꾸거나 상하 반전하지 않는다. 문서의 좌표·응수도 같은 변환을 적용한다. 구현 시 변환된 FEN을 산출하고 테스트에 고정한다.

### 수업 1 — 상대가 노리는 말 찾기

ID `protect-spot-v1`. 선수: 말 잡기. 보기 A / 함께 B / 혼자 C.
- 첫 문장: `상대가 다음에 잡을 수 있는 우리 말을 찾아 눌러요.`
- 정답 집합: 백 왕을 제외하고, 현재 배치에서 **흑이 합법적인 잡기로 취할 수 있는 백 말**. 현재 체스 엔진으로 계산하며 이 세 장면에서 각각 d4/a3/d5 한 개임을 검증한다.
- 입력은 말을 지목하는 것이며 백의 실제 이동/차례 소비가 아니다.
- 정답이면 공격하는 말→목표를 강조하고 `이 비숍/룩/나이트가 우리 룩/비숍을 노려요.` 다음 연습은 사용자 클릭으로 이동.
- 틀리면 `이 말은 지금 바로 잡히지 않아요. 상대 말이 갈 수 있는 곳을 살펴봐요.` 첫 오답에서 정답을 바로 표시하지 않는다.
- 도움 1: 공격할 수 있는 상대 말 강조. 도움 2: 공격 경로/착지점. 도움 3: 목표 말 강조.
- 왜: `내가 두기 전에 상대가 다음에 무엇을 잡을지 살펴봐요.`

### 수업 2 — 안전한 곳으로 피하기

ID `protect-escape-v1`. 선수: 공격 찾기. 보기 A / 함께 mirror(B) / 혼자 mirror(C).
- 첫 문장: `공격받는 말을 잡히지 않는 칸으로 옮겨요.`
- 학습 대상 말은 기준 배치에서의 목표 말. 다른 백 말 선택 시 `이번에는 테두리의 말을 지켜봐요.`; 이는 학습 과제 범위 제한이며 체스에서 금지된 수라고 말하지 않는다.
- 대상 말의 **모든 합법적인 이동** 허용. 이동 후 흑의 합법 수 중 이동한 말을 잡는 수가 없으면 이 연습의 성공. 공격 기물을 잡아서 위협을 없애는 수 역시 허용.
- 위험한 합법 수는 실제로 두고, 해당 말을 잡는 흑의 합법 응수 하나를 보여준다. 응수는 좌표 사전순으로 결정하여 재현 가능하게 한다.
- 성공: `이 칸에서는 상대가 다음 한 수에 이 말을 잡을 수 없어요.` 장기적으로 최선이라고 주장하지 않는다.
- 실패: `여기로 가도 상대가 잡을 수 있어요. 다른 칸도 살펴볼까요?`
- 도움 1: 공격 기물 강조. 도움 2: 선택한 목적지가 공격받는 이유. 도움 3: 통과하는 합법 수 한 개의 화살표. 도움은 무조건 답을 자동 실행하지 않는다.
- 왜: `움직일 수 있는 칸과 안전한 칸은 다를 수 있어요.`

### 수업 3 — 잡은 다음도 살펴보기

ID `protect-capture-v1`. 선수: 안전한 목적지. 보기 D / 함께 mirror(D) / 혼자 D에 백 나이트 c3 추가한 배치.
- 첫 문장: `룩으로 상대 폰을 잡아요. 잡은 뒤에도 룩이 안전한 곳을 찾아요.`
- 대상 백 룩의 모든 합법적인 **잡기**를 허용. 빈칸 이동은 `이번에는 폰을 잡는 두 방법을 비교해요.`로 설명하고 시도로 세지 않는다.
- 성공: 잡은 뒤 흑의 합법 응수에 해당 룩 잡기가 없음. D에서 Rxh2 통과, Rxe4 뒤 Bxe4는 실패 사례. mirror도 같은 관계.
- 나이트가 추가된 혼자 배치에서도 룩이 학습 대상. 나이트는 다른 판에서 같은 판단을 할 수 있는지 보는 배경 변화이며 새 규칙은 아니다.
- 실패: 애니메이션으로 폰 잡기→비숍이 룩 잡기를 보여준 뒤 `폰을 잡았지만 상대 비숍에게 룩을 잃었어요.`
- 성공: `폰을 잡고 룩도 지켰어요.`
- 왜: `잡을 수 있는 말이 보여도 바로 움직이지 말고, 상대가 내 말을 다시 잡을 수 있는지 살펴봐요.` 이는 모든 교환/희생이 나쁘다는 뜻이 아니며 더 깊은 수업에서 다룬다고 짧게 부연한다.

## 6. 판정·교재 응수 계약

- `attackers`는 시각적 공격 관계에 활용할 수 있으나, 성공/실패 판정은 핀·왕 안전을 포함한 합법 수로 확인한다.
- 상대의 합법 잡기를 조사할 때 원본 game.turn을 바꾸지 않는다. 복제본의 차례/선택 상태를 정리하고 검사한다. 검사 과정에서 반복 횟수/기록을 원본에 쓰지 않는다.
- 시범/오답 응수에 AI 난수나 현재 사용자의 대전 난이도를 사용하지 않는다. 검수된 예제 또는 실제 가능한 반박 수를 재현한다.
- ‘다음 수에 잡히지 않음’만 검사하는 범위를 명시한다. 엔진 평가값·정확도·Elo·장기 최선 수라는 표현은 금지.
- 성공 여부는 콘텐츠 술어로 계산한다. witness 수순은 테스트 근거이며 유일 정답 배열이 아니다.
- 구현 중 예제에 숨은 핀/초기 체크/다른 위협이 발견되면 목적에 맞게 최소 수정하고 명세·테스트에 근거를 기록한다. 잘못된 예제를 억지로 맞추기 위해 규칙 엔진을 변경하지 않는다.

## 7. 대전으로 연결

`이 배치로 대전`은 마지막 transfer 장면의 **원래 초기 배치**에서 표준 체스로 새 대전을 시작한다. 목표 성공 후 단순화된 결과판을 넘기지 않는다.
- 기존 대전의 난이도 선택을 사용. 선택값을 요약하고 시작 버튼으로 확정.
- 신규 `play.content.type='lessonPractice'`, version 1, lessonId/lessonVersion/sceneId를 저장. 초기 FEN은 ID로 신뢰된 교재에서 가져온다. 외부 파일의 임의 FEN을 신뢰하지 않는다.
- 기존 playContentValid/Game/Title/Initial/Panel와 콘텐츠별 저장 함수를 확장. 수업 연습 대전 아카이브 키 `lessonPractice`. 원정/협력/일반 대전 자료를 보존한다.
- 표준 승패·체크·승격·되돌리기·AI 취소를 재사용. 수업의 학습 판정으로 대국을 끝내지 않는다. 재대결은 같은 배치/실제 난이도.
- 기존 lessonPractice 저장이 있을 때만 이어하기/교체 선택. 수업 완료는 이 대전을 이겨야 얻는 것이 아니다.

## 8. 데이터·저장·백업

추가 파일 제안: `js/lesson-content.js`(교재와 순수 판정), `js/app-lessons.js`(상태/화면/입력). 기존 전역 스크립트 구조 유지.

교재 스키마:
```
{id, version:1, title, skill, prerequisites, scenes:[
 {id, role:'demo|guided|transfer', fen, task:'spot|escape|captureSafe',
  focusSquare, prompt, explanations, witnessSuccess, witnessFailure}
]}
```
문구는 정적 교재에서만 읽고 import된 설명 HTML을 렌더링하지 않는다.

`SESSION_KEYS.lesson=['lesson']`, 새 screen-lesson 추가. lesson 상태:
```
{lessonId, contentVersion:1, sceneId, sceneRole, phase,
 game, attemptStartGame, selected, attempts, helpLevel,
 result:null|'success'|'retry', responseMove:null|move,
 demoStep, progress:{guided:false,transfer:false}}
```
선택/시범 타이머 핸들/DOM 참조는 저장하지 않는다. `game`은 복원 시 ChessGame 인스턴스로 되살린다. 노출된 selected와 게임 내 selected 중 한 곳만 상태 원본으로 결정해 중복을 없앤다.

- 활동 세션은 v5, 백업은 수업 자료 또는 lessonPractice가 들어 있으면 v5. 기존 v1~v4 계속 읽는다. 구버전 앱은 v5를 거절하도록 버전 올림.
- `lesson_sessions_v1`: 수업 ID별 저장판. 공통 `sessions.lesson`은 마지막 활성 수업, 목록의 이어하기는 ID별 저장 조회. 서로 다른 수업 전환 시 마지막 수업 하나만 남기는 실수를 피한다.
- `lesson_progress_v1`: 수업별 완료/도움 사용 여부/마지막 단계. 완료는 guided와 transfer 성공 후 마무리 도달 시 기록. 도움 사용해도 완료 인정. 읽기나 시범 재생만으로 완료 안 됨. 도움 없이 다시 풀었으면 independent 기록 추가.
- 응수 중 저장/앱 종료 시 attemptStartGame으로 복귀하는 안정된 `choose` 상태로 저장. 이미 성공/실패 결과가 끝났으면 결과 그대로 복원. 복원하면서 갑자기 AI/시범이 움직이지 않는다.
- undo는 안정된 시도 시작 스냅샷. 스냅샷에도 IDs·게임·단계 검증 적용. 비활성 수업 목록 자료도 백업 크기/타입/버전/기물·좌표·scene 관계를 검증한다.
- 백업 검증은 unknown lessonId/version, 잘못된 phase, 다른 scene의 game 초기 참조, 초과 배열, 범위 밖 좌표, 임의 스크립트 문자열을 거절한다. 저장된 현재 배치는 합법 진행으로 달라질 수 있으므로 초기 FEN과 항상 같은지 비교하면 안 된다.
- 프로필 변경·파일 이동 후 수업 진도/완료와 undo가 동일해야 한다. 모든 프로필 기능은 동일.
- 구매 권한은 미래에 별도 설계. 프로필 백업의 일반 JSON 완료 필드로 유료 구매를 인증하지 않는다.

## 11. 사용자 관찰 (구현 후 별도)

아이/어른과 체스 경험, 혼자/부모 시범 조건을 기록한다. 첫 설명 없이 시작→첫 막힘→되돌리기/도움→다른 배치에서 적용→자발적 다음 수업 선택을 관찰한다. 3~5분은 목표 길이일 뿐 타이머/합격 기준이 아니다. 강제 평가·연속 출석으로 진행을 요구하지 않는다.

짧은 기록 양식: 날짜 / 경험 / 수업 / 첫 막힘 / 필요한 설명 / 다른 배치에서 혼자 성공했는가 / 다음 수업을 스스로 선택했는가 / 대전에 사용했는가.

3개 수업에서 자발적 사용과 학습 전이를 확인한 뒤에 전체 유료 과정 제작·가격 실험을 별도로 승인받는다.

## 12. 설계 시 교재 확인 기록

`LESSON_SCENES_V1.json`에 9개 장면의 구체적인 FEN/역할/대상 좌표/성공·실패 예시와 현재 엔진으로 계산한 합법 수 분기를 함께 기록했다. 2026-11-07에 현재 `tests/harness.cjs`로 모든 초기 상태가 playing이며, 지목 수업의 실제 합법 잡기가 존재하고 이동 수업의 성공 수가 존재함을 확인했다. A의 왕을 a1에 두면 룩이 핀에 걸리므로 a2로 수정했다. 함께 연습 B의 비숍 피하기는 모든 합법 이동이 안전할 수 있으므로 witnessFailure=null을 허용한다. 실패를 만들기 위해 불법 수를 재생하지 않는다.

이 검사는 체스 엔진 기준의 설계 확인이다. 전체 구현 테스트·체스 지도자 검수·어린이 관찰을 했다는 의미가 아니다. 구현자는 JSON의 예시뿐 아니라 명세 §10 전체를 검증해야 한다.

수업 1에서 상대의 잡기를 시범으로 보여줄 때는 `상대 차례라면 이렇게 잡을 수 있어요`라는 예측 화면으로 구분한다. 원래 백 차례의 학습 게임에 흑의 수를 불법 적용하지 않는다. 예측용 복제 판에서만 재생하고 원래 배치로 돌아온다.
