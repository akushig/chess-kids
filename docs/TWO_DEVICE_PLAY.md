# 두 기기 대전: 같은 방(QR) · 멀리서(초대장)

작성: 2026-11-08 · 빌드 `2026.11.08.4` · 검증: 단위 170/170, 브라우저 17종 · 상태: **구현 완료 · 자동 검증 완료(한 컴퓨터 안의 브라우저 두 개) · 실제 휴대폰 두 대로는 확인하지 않음**

사용자 요청(2026-11-08): "같은방, 멀리서 실시간 두가지 방법으로 구현해줘. 먼저 체스 대전에 적용해줘. 잠깐 인터넷이 끊기더라도 재연결 등의 폴백 로직등도 구현해줘." 바로 앞에서 "서버 없이 두 기기에서 대전을 구현할 수 있어?"라고 물었고, 서버 없는 방식의 한계(멀리서 실시간은 통신사 망 등에서 실패할 수 있음)를 설명한 뒤 받은 요청이다.

## 1. 쓰는 법

대전 → 상대 **📱 두 기기로** → 연결 방법 · 내 색(흰색 먼저 · 검은색 · 무작위) · 판 설정(왕 구하기 도움 · 짧은 판).

| 방법 | 초대하는 사람 | 초대받는 사람 |
|---|---|---|
| **같은 방** | `📷 내 QR 보여 주기` → 친구 화면에 QR이 나오면 `📷 친구 QR 찍기` | `📥 친구 QR 찍기` → 내 화면에 나온 QR을 친구가 찍음 |
| **멀리서** | `💌 초대장 만들기`(보호자 확인) → 메신저로 보냄 → 친구가 보낸 **답장 코드**를 붙여 넣음 | 링크를 누르거나 `📥 받은 코드 넣기`(보호자 확인) → 답장을 메신저로 보냄 |

- 같은 방은 두 기기가 같은 와이파이에 있어야 한다. 와이파이가 없으면 한 휴대폰의 핫스팟에 다른 휴대폰을 연결한다(인터넷이 없어도 된다).
- 카메라가 없으면 같은 방에서도 '코드로 보내기 / 받은 코드 넣기'를 쓸 수 있다.
- 대국 화면: 위 줄은 친구(아이콘·이름·잡은 말), 아래 줄은 나. 검은색이면 판을 돌려 내 말이 아래에 온다. 오른쪽 위 점은 연결 상태(🟢 연결됨 · 🟡 자리 비움/약함 · 🔴 끊김).
- 할 수 있는 것: 내 차례에만 두기, 💡 한 수 보기(내 차례), 🤝 비기기 제안(둘 다 동의해야), 🏳 기권, 끝난 뒤 🔁 한 판 더(색을 바꿔 새 대국), 표정 4개(👍 😮 🙂 😅). **글 채팅은 없다.**
- 하지 않는 것: 되돌리기, 한 수 시간 제한(두 기기 사이 시간 차이 때문).

## 2. 서버 없이 잇는 방법

- 두 기기를 **WebRTC 데이터 채널**로 직접 잇는다. 연결에 필요한 정보(ICE 자격, DTLS 지문, 후보 주소)를 사람이 옮긴다: 같은 방은 QR을 서로 한 번씩 찍고, 멀리서는 메신저로 두 번 주고받는다.
- 연결 코드: `CK1` + 종류(`o` 초대 · `a` 답장 · `m` 편지) + `.` + base64url 본문. SDP 전체가 아니라 바뀌는 값만 담아 **약 200자**다(QR 버전 약 10). 받는 쪽은 정해진 틀로 SDP를 다시 만든다. 형식 검사에 맞지 않는 코드는 거절한다(`js/net-peer.js`).
- 멀리서는 자기 공인 주소를 알아내려고 **공개 STUN 서버**(Google `stun.l.google.com`, Cloudflare `stun.cloudflare.com`)에 묻는다. 이 서버들은 기기의 공인 IP를 보지만 대국 내용은 지나가지 않는다. 대국 내용은 어떤 서버에도 저장되지 않는다.
- 중계(TURN) 서버가 없으므로 **양쪽이 모두 대칭형 NAT(일부 통신사 망·회사·학교망)이면 멀리서 실시간 연결이 안 될 수 있다.** 그때는 §3의 편지로 이어 둔다.

## 3. 끊겼을 때 (폴백 단계)

| 단계 | 상황 | 동작 |
|---|---|---|
| 1. 자동 복구 | 6초 동안 아무 신호가 없거나 연결이 '끊어짐'으로 바뀜 | 🟡 **약함 · 다시 잇는 중**. 2초마다 살아 있다는 신호를 보낸다. 같은 주소로 인터넷이 돌아오면 브라우저가 연결을 되살리고, 되살아나면 **수 목록을 서로 비교해 맞춘다**. 약한 동안에도 내 수를 둘 수 있다. |
| 2. 끊김 | 약함이 20초 더 이어지거나, 연결이 닫힘 (통로가 살아 있으면 끊김 중에도 신호를 계속 보낸다) | 🔴 **끊김**. `🔄 다시 연결`·`📥 받은 코드 넣기`(멀리서는 `💌 편지로 보내기`도). 끊긴 동안에도 내 차례면 둘 수 있다. 원래 연결이 늦게라도 살아나면 다시 연결 화면을 닫고 이어 간다. |
| 3. 다시 연결 | 한 사람이 `새 QR/새 초대장` | 같은 대국 번호로 새 연결을 만든다. 연결되면 수 목록을 맞춘다(끊긴 동안 둔 수도 전해진다). 같은 방 ↔ 멀리서 방법을 바꿔 다시 이을 수도 있다. 이어 두기는 보호자 확인을 다시 묻지 않는다. |
| 4. 새로고침·앱 종료 | 연결 정보가 사라짐 | 대국 기록은 기기에 남는다. 대전 → `📡 ○○와 두던 대국 이어 두기`(홈에도 내 차례일 때 카드) → 3단계로 다시 연결. |
| 5. 편지 | 실시간 연결이 끝내 안 됨 | `💌 편지로 보내기`: 지금까지의 **수 목록 전체**를 담은 코드를 메신저로 보낸다. 받은 쪽은 `받은 코드 넣기`나 링크로 연다. 같은 편지를 두 번 넣어도 판은 그대로다. 나중에 실시간 연결이 되면 저절로 맞춰진다. |

- **수 목록 맞추기 규칙**: 한쪽 목록이 다른 쪽의 앞부분이면 긴 쪽을 쓴다. 서로 다르면(정상적으로는 생기지 않음) **처음 초대한 쪽** 목록을 쓰고 안내한다. 받은 목록은 처음부터 다시 둬 보고 규칙에 맞을 때만 쓴다.
- **수 하나하나**: 보낸 수에는 순번이 있다. 받은 쪽은 순번·차례·규칙을 확인해 두고 '받았어요'를 돌려준다. 겹친 수는 다시 받았다고만 하고, 순번이 빠졌거나 다르면 맞추기를 부탁한다. 보낸 수가 아직 확인되지 않았으면 "내 수를 친구에게 보내는 중"으로 보인다.
- **앱을 내리면**: "잠깐 자리 비움"을 알린다. 친구 쪽은 3분까지 끊김으로 세지 않는다. 다시 보이면 맞추기 인사를 보낸다.
- **링크로 새 탭이 열리면**: 같은 브라우저에 체스 화면이 이미 열려 있으면 그 화면에 코드를 넘기고 새 탭에는 "열려 있던 화면으로 돌아가요"를 보여 준다(답장은 초대장을 만든 화면에서만 쓸 수 있다).

## 4. 안전 · 아동 보호

- 처음 연결하는 **멀리서 새 대국**은 초대·받기 모두 보호자 확인(곱셈)을 거친다. 같은 방과 이어 두기는 묻지 않는다.
- 초대장·답장 화면에 "이 기기의 인터넷 주소가 들어 있어요. 아는 친구에게만 보내요"를 보여 준다.
- 상대에게 보내는 것: 프로필 이름(최대 12자로 잘라 보임)과 아이콘, 수 목록, 기권·비기기·한 판 더·표정. 받은 이름은 HTML로 넣지 않고 글자로만 보이며, 아이콘은 앱의 정해진 8개만 받는다.
- 받은 모든 수는 내 기기의 규칙 엔진(`js/chess.js`)으로 다시 확인한다. 메시지 크기는 16KB, 수 목록은 600수까지만 받는다. 표정은 4초에 3개까지만 보인다.

## 5. 저장

- `net_game_v1`(프로필별): `{v:1, gid, method, inviter, color, small, moves[], end, acked, peer:{name,icon}}`. 놀이 저장(`sessions`·`last_session`)과 섞이지 않는다. 그래서 컴퓨터 대전을 새로 시작해도 두 기기 대국은 그대로다(두 기기 대국은 한 번에 하나).
- 프로필 파일에는 그대로 들어가고, 불러올 때 수 목록을 다시 둬 봐서 검사한다. `play_settings`에 `view:'net'`, `netMethod`, `netColor`가 더해졌다(상대 모드 값은 예전처럼 `ai`·`friend`만).

## 6. 한계와 출시 전 할 일

- **실제 휴대폰 두 대로 확인하지 않았다.** 자동 검사는 한 컴퓨터 안 브라우저 두 개라, 공유기·통신사·카메라 초점·화면 밝기 차이는 검증되지 않았다.
- 멀리서 실시간: 대칭형 NAT, 답장이 아주 늦은 경우(몇 분 뒤), 와이파이 ↔ LTE 전환은 실패할 수 있다(→ 다시 연결 또는 편지). 확실하게 하려면 작은 신호·중계 서버(TURN)가 필요하다 — `docs/SERVER_FEATURES_PLAN.md` §3.
- 손님용 와이파이 등 기기끼리 통신을 막은 공유기에서는 같은 방 연결도 안 된다(핫스팟 안내).
- 카카오톡에서 초대 링크를 누르면 카카오톡 안의 브라우저에서 열릴 수 있다. 그러면 아이의 프로필·별과 따로 저장되므로, 체스 앱(설치한 앱이나 평소 쓰는 브라우저)에서 `받은 코드 넣기`로 여는 것이 좋다(공유 문구에도 안내).
- 둘이 동시에 '한 판 더'를 누르면 대국 번호가 작은 쪽 제안으로 정해진다.
- 아이폰은 앱을 내리면 연결이 금방 끊길 수 있다(→ 돌아와서 다시 연결).
- 앱으로 감쌀 때: 웹뷰 카메라 권한(Android `WebChromeClient.onPermissionRequest`+`CAMERA` 권한, iOS `NSCameraUsageDescription`), 링크(`#net=`)를 앱으로 여는 딥 링크, 공유(`navigator.share`) 동작, 개인정보처리방침에 STUN·두 기기 직접 연결 설명.
- 외부 코드: QR 만들기 `js/vendor/qrcode.js`(qrcode-generator 1.4.4, MIT, Kazuhiko Arase), QR 읽기 `js/vendor/jsQR.js`(jsQR 1.4.0, Apache-2.0, 전문 `js/vendor/LICENSE-jsQR.txt`). jsQR은 브라우저 QR 인식이 없을 때만 불러온다(오프라인 대비 미리 저장).

## 7. 코드와 검사

- `js/net-peer.js`: 연결 코드 만들기·읽기, SDP 줄이기·다시 만들기, `NetLink`(연결 하나: 상태 · 신호 · 약함/끊김 판단 · 검사용 `debugMute`), QR 그리기, 카메라로 QR 찍기.
- `js/app-net.js`: 대국 기록, 메시지 처리(인사·수·받음·기권·비기기·한 판 더·표정), 수 목록 맞추기, 대국 화면(`renderPlayNet`), 연결 화면(`screen-net`), 다시 연결, 편지, 대전 설정의 '두 기기로', 링크 처리.
- 기존 코드에 더한 것: `js/app-play.js`(모드 `net`: 내 차례 판단 `playMineToMove`, 판 돌리기, 결과 버튼), `js/app-session.js`(두 기기 대국은 놀이 저장 대신 대국 기록), `js/app-core.js`(돌린 판의 잡기 애니메이션), `js/app-profiles.js`(가져오기 검사), `js/app-home.js`(내 차례 카드), `css/style.css`("두 기기 대전" 묶음).
- 단위 `tests/net.test.cjs`(10): 코드 줄이기·다시 만들기(Chrome·Firefox 모양), 고친 코드 거절, 편지, 수 목록 맞추기, 메시지 처리(겹침·빠짐·차례 아님), 다시 연결 인사·이름 검사, 기권·비기기·한 판 더, 편지 적용, 저장 범위·프로필 파일, QR 그림을 jsQR로 다시 읽기.
- 브라우저 `tests/net-browser.cjs`: 브라우저 두 개(360×640 · 1280×900), **가짜 카메라 영상에 상대 QR을 비춰 실제로 찍기**(한쪽은 브라우저 QR 인식, 한쪽은 jsQR), 탭으로 두기, 표정, 잠깐 끊김(9초) 뒤 자동 복구와 그동안 둔 수 전달, 오래 끊김(30초, 양쪽 모두 '끊김') 뒤에도 인터넷이 돌아오면 저절로 복구, 연결 닫힘 → 끊긴 동안 둔 수 → QR 다시 연결, 새로고침 → 코드로 다시 연결, 비기기·한 판 더(색 바꿈·판 돌림)·기권, 멀리서 새 대국(보호자 확인) → 편지 주고받기 · 링크로 연 새 탭의 코드 넘기기 · 잘못된 코드 안내. 연결 상태가 바뀌어도 판 위치 그대로, 주요 버튼 44px 이상, 가로 넘침 없음. 스크린숏: `docs/product-review/two-device/`.
