# 컴퓨터 대전 10단계

빌드 `2026.11.03.1`. 기존 매우 쉬움은 **1단계**, 기존 매우 어려움은 **8단계**다. 기존 쉬움·보통·어려움은 각각 3·5·7단계로 대응한다.

| 단계 | 이름 | 두는 방식 | 기본 탐색 깊이¹ | 계산 예산² | 수 선택 여유³ | 기존 대응 |
|---|---|---|---|---|---|---|
| 1 | 매우 쉬움 | 모든 합법 수 중 무작위 | 없음 | 탐색 안 함 | 전체 합법 수 | 매우 쉬움 |
| 2 | 첫걸음 | 50%는 무작위, 50%는 즉시 점수 비교 | 1회 이동 | 0.15초 | 300 | 새 중간 단계 |
| 3 | 쉬움 | 당장 잡을 말과 기물 위치를 비교 | 1회 이동 | 0.25초 | 150 | 쉬움 |
| 4 | 익숙해지기 | 컴퓨터의 수와 상대의 응수까지 비교 | 2회 이동 | 0.4초 | 100 | 새 중간 단계 |
| 5 | 보통 | 응수와 말을 주고받는 잡기 연쇄도 탐색 | 2회 이동 + 잡기 연쇄 | 0.6초 | 60 | 보통 |
| 6 | 생각 연습 | 한 단계 더 앞을 읽고 선택 범위를 좁힘 | 3회 이동 + 잡기 연쇄 | 0.9초 | 40 | 새 중간 단계 |
| 7 | 어려움 | 같은 깊이에서 더 신중하게 선택 | 3회 이동 + 잡기 연쇄 | 1.5초 | 20 | 어려움 |
| 8 | 매우 어려움 | 기존 최고 난이도의 깊이·시간·선택 기준 유지 | 6회 이동 + 잡기 연쇄 | 1.2초 | 5 | 매우 어려움 |
| 9 | 고수 | 더 깊고 오래 탐색하고 평가상 최선의 수를 선택 | 8회 이동 + 잡기 연쇄 | 2.5초 | 0 | 기존 최고보다 상향 |
| 10 | 최고 도전 | 가장 큰 탐색 깊이와 시간 예산 사용 | 10회 이동 + 잡기 연쇄 | 5초 | 0 | 기존 최고보다 상향 |

1. 이동 1회는 한쪽이 한 번 두는 수(반수, ply)다. 표의 깊이는 목표 상한으로, 시간이 부족하면 마지막으로 **완전히 계산한 깊이**의 결과를 사용한다. 체크 대응과 잡기 연쇄는 표보다 더 깊게 탐색할 수 있다.
2. 계산 예산은 일부러 기다리는 시간이 아니다. 일찍 탐색을 마치면 먼저 응수하며, 아이가 수를 따라갈 수 있도록 기존 최소 대기 0.4초는 유지한다. 7·8단계의 시간 예산은 기존 값을 보존했다. 7단계는 기본 깊이가 3으로 제한되고, 8단계는 6까지 탐색한다. 기기·국면에 따라 실제 깊이와 시간은 다르며 시간 확인 주기와 준비 작업으로 약간의 초과가 가능하다.
3. 수 선택 여유는 최선 점수에서 허용하는 차이(센티폰, 폰 한 개의 기물 가치=100)다. 예를 들어 150은 최선보다 평가가 최대 150 낮은 수까지 선택 후보로 둔다는 뜻이다. 0인 9·10단계도 동점인 수 중에서는 무작위로 고른다. 실제로 잘못 둔 수의 가치나 실수 확률을 보장하는 값은 아니다.

## 선택 화면과 저장

- 1~10 숫자 버튼, 선택한 단계의 이름·설명, ‘단계별 차이 보기’ 표를 한국어·영어로 제공한다. 대국 중에도 단계 번호를 표시한다.
- 기존 프로필 설정과 진행 중인 대국·되돌리기 기록을 새 단계로 이관한다. 난이도 버전 번호를 저장해 다음 실행에서 다시 변환하지 않는다.
- 어린이 기본값은 1단계, 어른 기본값은 기존 보통에 해당하는 5단계다. 힌트·시범은 기존 쉬움(새 3단계), 선택형 시간 초과 도우미는 기존 보통(새 5단계)을 유지한다.
- AI는 Web Worker에서 계산한다. Worker를 사용할 수 없는 환경에서는 화면이 오래 멈추지 않도록 주 스레드 계산 예산을 0.25초로 제한한다. 이 경우 높은 단계도 목표 깊이까지 도달하지 못할 수 있다.

## 확인한 범위

정해진 단계마다 반드시 전 단계와 다른 수를 두거나 항상 이긴다는 의미는 아니다. 9·10단계는 8단계보다 더 큰 탐색 자원과 더 엄격한 선택 기준을 사용한다. 간단한 폰 엔드게임을 실제 Worker에서 실행해 8·9·10단계가 각각 6·8·10 깊이까지 완료하는 것을 확인했다.
